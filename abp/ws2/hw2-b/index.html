Homework until 16 Nov, Part B: Find out why your mail AI assistant missed the kimchi

Your mail AI assistant drafts answers based on earlier mails. In the preparatory homework, you first sent a mail about kimchi to your test Gmail account, then asked it about Korean food, and saw the power of semantic search. However, when you send another mail that asks about Korean food, you see that the mail AI assistant misses the info about the kimchi in its search. Let’s use Claude Code to find out why. Then Claude Code will try to fix the search, and you measure whether the fix does better.

7. See the mistake: ask your mail AI assistant about Korean food

  1. In n8n, check that these four workflows are published:

    • WS2.0 - Embed Mails
    • WS2.3 - Triage New Mail
    • WS2.4 - Reply with Approval
    • WS2.4 - Approvals Page

    Published means: the dot on the button Publish is green.

  2. First the kimchi mail. Did you send Kimchi for Monday in step 12 of the preparatory homework? If yes, go on with 3. If you are not sure, search your test Gmail account for kimchi.

    If you did not send it, send it now: from your SKKU account, send this mail to your test Gmail account. Copy the subject and the text, then sign with your first name:

    Kimchi for Monday
    Hi,

This weekend my family makes kimchi for the winter (gimjang).
I will bring a box of it for everyone at the workshop on Monday.

    Wait two minutes: kingo-pod copies the mail into its database, and WS2.0 adds it to the search.

  3. Now the question. From your SKKU account, send a second mail to your test Gmail account. Copy the subject and the text:

    Is there any Korean home made food?
    Hi Vince, I'm getting hungry! Please reply.

  4. Wait two minutes. Then open the page with the drafts that wait for you: http://localhost:5678/webhook/approvals

  5. Read the draft of the reply to Is there any Korean home made food? (A draft of a reply to the kimchi mail may wait there too: leave it.) Most likely the draft says that nothing is known about Korean food and that someone will follow up. The kimchi mail is in your database, yet the draft does not use it.

Does your draft mention the kimchi? Then the search was lucky this time. Go on anyway: in step 10 you measure it.

Side note: the address in sub-step 4 is a webhook

The address you opened in sub-step 4 (http://localhost:5678/webhook/approvals) is a webhook, that is, an address where someone (here, that is you) can call n8n. In other words, n8n hands out a hook that you can pull. In this case, your browser pulled the hook by calling the address, and the n8n workflow WS2.4 - Approvals Page answered: it read the drafts that wait for you from the database, made a web page of them, and sent this page back to your browser. The page carries a little sticker that you do not see: “pull the hook again in 15 seconds”. So your browser does that for you, and the page is never more than 15 seconds old. n8n looks into the database only when someone pulls the hook: close the page, and WS2.4 - Approvals Page rests.

A webhook is how someone else calls n8n. The other way round, n8n calls someone else, often with an HTTP Request node: WS2.4 - Reply with Approval, for example, calls the Langflow flow Draft Reply (Enron) with one.

8. Let Claude Code find the cause

Start Claude Code (you find cd ~/kingo-pod && ./kingo claude in your terminal’s command history with the up arrow) and paste this:

My mail AI assistant drafted a reply to my mail "Is there any Korean home made food?"
without the mail "Kimchi for Monday", which is in the database. Find out why.

Look at:
- the last run of WS2.4 - Reply with Approval in n8n: what it sent to the Langflow flow
  Draft Reply (Enron), and what came back as sources;
- the code of the component Mail Search in that flow.

Do not change anything. Then explain the cause to me in plain words.

Claude Code reads the run, the flow and the code. To this end, it runs several commands to dig deeper and to find the reason. Before running a command, it asks you for permission. Most of these requests are searches: Claude Code looks into your database, or into the runs that n8n keeps. A search changes nothing, so you can approve it.

So many requests in a row are tiring, right? Did you switch to auto mode? Press Shift+Tab until the line under your text says auto mode on. Then a model checks each command and runs what it judges safe, without asking you. More about the modes: Can we tell Claude Code to just do its job?

Did you stop Claude Code by accident, or say no to a request? Type continue, and Claude Code goes on.

At the end, Claude Code answers your question: it explains why the search did not find the kimchi. Read this answer twice (the answer at the end, not the reasons Claude Code gives for its requests): this is the most important finding of this part.

Feel free to ask Claude Code to say the answer in simple words if you find it too complicated:

Say this again in simple words.

Stuck? Help for step 8

9. Let Claude Code fix the search, in a copy of the flow

The fix goes into Langflow only, not into n8n: n8n builds the mail text, and the prompt and the check of the draft still need all of it. Only the search should get less.

Make a copy of the Langflow flow Draft Reply (Enron) and name it
"Draft Reply (Enron) - Search Fix". Put the copy into the same Langflow project
(folder) as the original.

In the copy only, change what goes into the search of Mail Search, following the cause
you found. The prompt and Check Draft keep the whole mail.

Do not change the original flow, and do not change n8n.

You should see the new flow Draft Reply (Enron) - Search Fix in your Langflow, next to the original. The original is unchanged, and Claude Code saved its JSON in ~/kingo-pod/claude/backups/.

Stuck? Help for step 9

10. Measure: three mails, two flows

One mail proves nothing: a fix for one mail can break another. So you test both flows on three mails. All three are in your database.

Run both flows, Draft Reply (Enron) and Draft Reply (Enron) - Search Fix,
on three mails from the table n8n_workshop_mail.messages.

Give each mail to the flow as WS2.4 does (From, To, Date and Subject lines, then the text),
and as its date one second before the mail was sent, so that the search does not find
the mail itself.

The mails, by subject, and the sources I expect:
1. "Is there any Korean home made food?" (my own mail):
   "Kimchi for Monday"
2. "Re: FW: Wharton Resume Submission - Summer Intern" (from Kristin Gandy, 26 January 2001):
   "FW: Wharton Resume Submission - Summer Intern"
3. "Dr. Michelle Foss- Energy Institute" (from Aisha Jamal, 23 April 2001): one of
   "Re: Tiger Team Event", "Re: Leonard Hilton Reception-DIRECTIONS-PARKING",
   "Wharton Business Plan Competition", "@Jones: News and Information from the Jones School",
   "Invitation-WhartonETEvent-Apr20/PlsRSVP"

Show me a table: for each mail and each flow, was an expected source among the sources?

You should see a table with six answers. When we measured the search alone on 10 November, our table looked like this:

MailDraft Reply (Enron)Draft Reply (Enron) - Search Fix
Korean home made foodnot foundfound
Wharton Resume Submissionfoundfound
Energy Institutefoundnot found

In our table, the fix brings in the kimchi, and the Energy Institute drops out: the fix helped one mail and hurt another.

Your table may look different. Your mailbox holds other mails than ours, and Claude Code may have built your fix in another way. Read your own table:

  • Where did the fix help?
  • Where did it change nothing?
  • Did it hurt anywhere?

That is the lesson of this part: a change is better only when you measured it on more than one case.
