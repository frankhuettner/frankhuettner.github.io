You do not need this part for the course. It is for the day when one folder, one session or one API key is not enough any more: then you know that there is a way, and where to find it.

12. Give Claude Code one more folder

Claude Code works in a sandbox, nono: a fence around Claude Code, as in the last homework (Better safe than sorry). Inside the fence, it works as it likes. Outside, it can read nothing and change nothing. Usually, that is just right. But say you start a second website, and Claude Code should take over the colours of your first one. Your first website is outside the fence.

Quiz. Say Claude Code writes: “I cannot read ~/projects/my-first-project. Type /add-dir ~/projects/my-first-project, and I can.” You type it. What happens?

  • Claude Code can now read your first website
  • Claude Code still cannot read it
Show the answer

It still cannot. Two things decide what Claude Code may read:

  • Claude Code’s own list of the folders that it works in. Outside them, it asks you first. /add-dir puts one more folder on the list.
  • The sandbox, the fence. kingo sets it up when Claude Code starts, and nothing inside can move it: not Claude Code, not /add-dir, not your “yes”.

So /add-dir changes only the list. Claude Code then tries to read the folder, and the sandbox says no: Operation not permitted on a Mac, Permission denied on Windows. To give Claude Code one more folder, you start it again, with that folder. Claude Code gives you the line for it.

For a file or two: copy them in. For example, Claude Code shall read a report that is in your Downloads:

  1. Open the folder where Claude Code works, as in step 10. For your first website on a Mac, paste this line into a second terminal tab:

    open ~/projects/my-first-project

    On Windows:

    cd ~/projects/my-first-project && explorer.exe .

  2. Copy the file into this folder. Click the file where it is now, and press Cmd+C on a Mac or Ctrl+C on Windows. Then click into the folder that you opened, and press Cmd+V or Ctrl+V. On Windows, you can also drag the file from a Windows folder into it.

  3. Tell Claude Code the name of the file, for example: “Read report.pdf in this folder, and tell me its three main points.”

That is all: you do not start Claude Code again, and the fence stays as it is. Claude Code works with the copy. Your file in Downloads stays as it is: Claude Code cannot read it or change it.

Want to give access to an entire other folder? Then use --read. Your turn: start a second website that reads your first one.

  1. Make its folder. Is Claude Code still running? Type /exit first. Then paste this line into your terminal:

    mkdir -p ~/projects/my-second-project

  2. Start Claude Code there, with your first website to read:

    kc ~/projects/my-second-project --read ~/projects/my-first-project

    Before Claude Code starts, kingo names the folder that Claude Code may also read. You did not make the short commands of Part E? Then go into ~/kingo-pod first, and start it with ./kingo claude --in ~/projects/my-second-project --read ~/projects/my-first-project.

  3. Paste this prompt into Claude Code:

    Read my first website in ~/projects/my-first-project. Make a one-page website here about me, in the same colours and fonts. Ask me three questions about me first. You are done when index.html opens in a browser and looks like a sister of my first website. Look at both pages before you say that you are done.

  4. Test the fence. Paste:

    Change the title of my first website to "Hello".

    Claude Code says that it cannot, or it asks for your OK: then say yes, and watch the sandbox say no. Claude Code may read your first website, not change it.

The folder is open for this one start. Start Claude Code without --read, and the fence is where it was before: no folder stays open by accident.

Done: you gave Claude Code one more folder, and you saw the fence hold.

Claude Code should change the files there, too?

Then start it with --write in place of --read. Claude Code may then read, change and delete everything in that folder: give --write only to a folder that has a copy (step 8). In the course, for example, Claude Code can then put a file where your Langflow flows find it: Langflow sees your folder ~/kingo-pod/shared as /app/shared.

kc --write ~/kingo-pod/shared

What kingo takes. A folder inside your home folder, and not too much of it: not your home folder itself, not Desktop, Documents, Downloads or Library as a whole, no hidden folder (there, programs keep their keys), no Windows folder. A folder inside one of them is fine, also in Library: on a Mac, Dropbox, OneDrive and iCloud Drive keep their files there. Is your file somewhere else? Copy it in, as above.

Before you open a folder, ask two things. Does Claude Code need all of it? And may these files go to the company that runs the model? What Claude Code reads goes into the conversation, and with it out of your laptop (step 1).

Next time. When Claude Code needs files from elsewhere, copy them in, or start it with --read and the smallest folder that holds them.

From nono’s page on Claude Code: “add extra directory access”, and from its security model: a program in the sandbox “cannot expand its own kernel policy”. Anthropic’s page on permissions: working directories and /add-dir. kingo-pod: ./kingo claude help.

13. Work in two sessions at once

Claude Code can work in two terminal tabs at once: for example on your website in one tab, while you ask about your flow in the other. Each tab is a session of its own, in a sandbox of its own.

Your turn. Open a second terminal tab (how).

New here? What is different for you in 2 and 3

In 2, start the second session for your practice folder. Paste this line in place of the one there:

kc ~/projects/practice

In 3, ask it: “What does plan.md say?”

  1. In the first tab, start Claude Code for your website:

    kc ~/projects/my-first-project

  2. In the second tab, start it for the course:

    kc

  3. Ask each one something different. Ask the one of the course, for example: “Which flows are in my Langflow?” Both answer, each on its own.

Quiz. You ask both sessions to change the greeting of the same Langflow flow, at the same time. What happens?

  • The second session sees the first one at work, and waits
  • The two do not know about each other: one change can be lost
Show the answer

One change can be lost. Each session takes the flow, changes it, and puts the whole flow back. The one that comes second puts back its own version, without the change of the first, and nobody gets a warning. So give each session its own thing: its own folder, its own flow or workflow. Both should change one flow? Then one after the other.

Do you use Git? Two sessions in one repository

Two sessions in one repository share more than the files: they share the branch, and each commit and each push. So one session may commit or push the half-done work of the other.

  • The simple rule: only one session commits and pushes. The other one only reads, or works in another folder.
  • Two tasks in one repository at the same time? Give each session a worktree. A worktree is a second folder of the same repository, with its own files and its own branch. Each session changes only its own folder. When both are done, you bring the two branches together, as with any branch.

From Anthropic’s page Run parallel sessions with worktrees: the page also shows how to start one.

With your OpenRouter key: as many as you like. You can start Claude Code in three tabs, in four, or in more: open one more terminal tab, and start it there with kc and a folder. Each session is a conversation of its own: it does not know what you said in the other tabs. All of them pay with your one OpenRouter key, and you pay for each session. So the credit limit of your key counts for all of them together.

With --login: one at a time. kingo starts no second kcl while one runs: two at once break the login, because of a bug in nono, the sandbox that keeps your login. For a second session at the same time, start it with kc, with your OpenRouter key.

Done: two sessions at once, each with its own thing.

Next time. When you work in two sessions at once, give each its own folder or its own flow.

From Anthropic’s page Run parallel sessions with worktrees: each session gets a copy of its own, “so changes don’t collide”. kingo-pod: ./kingo claude help, its lines on --login.

14. Give a project a key of its own

So far, all your sessions pay with one OpenRouter key. In the course, it is the key that Yanbo gave you. One key means one credit and one sum for everything: the course, your website, and every other project.

Make a key of your own. The key from Yanbo is for the course. For a project of your own, make your own key: then you see on openrouter.ai what the project costs, and you set its limit yourself. On openrouter.ai, make an account and add credits. Then open Settings, then Keys, make a key, and give it a credit limit: the key stops at that amount. You pay for these credits yourself, so this is your choice.

kingo has one command to give a project such a key. You start Claude Code as you know it, and you add --key and a name: kc ~/projects/my-first-project --key website. Then the key with the name website pays for this session, and not your first key. Before Claude Code starts, kingo says so: Claude Code's model is paid with your OpenRouter key "website". This gives you three things:

  • You see what this project costs. OpenRouter counts for each key what it used.
  • The project gets a credit limit of its own. When Claude Code goes in circles in this project, it stops at that amount, and the credit of your other key stays.
  • The project can use another provider. A provider is the service that Claude Code sends the conversation to. It runs the model itself, or it passes the conversation on to a server that does. In the course, the provider is OpenRouter. With a key of its own, a project can use another one: for example Anthropic’s API, or a model on your own laptop. Anthropic is the company that makes Claude Code and the Claude models.

The command, piece by piece. In its longest form, it has four pieces:

You writeWhat it means
kc ~/projects/my-first-projectStart Claude Code in this folder, as before.
--key websiteThe key with the name website pays. You choose the name.
--provider anthropicWhich provider: anthropic is Anthropic’s API, ollama is a model on your laptop, and an address that starts with https:// is any other provider. For OpenRouter, you leave this piece out.
--model sonnetWhich model. For OpenRouter and for Anthropic’s API, you can leave this piece out: then you get their usual model.

You did not make the short commands of Part E? Then go into ~/kingo-pod first. Write ./kingo claude --in in place of kc when a folder follows, ./kingo claude when no folder follows, and ./kingo in place of kingo.

About the name.

  • What is the name? A word that you choose: small letters, digits and -. It is kingo’s name for the key. It need not be the name that the key has on the provider’s website, but the same name is the easiest to remember.
  • What does kingo keep under a name? Three things: the key, its provider, and its model. The first start with a new name asks for the key, and takes the provider and the model from your line. From then on, --key and the name are enough.
  • Where does kingo keep them? On your laptop, in the folder ~/.config/kingo/, with your other keys. This folder is outside the sandbox: Claude Code cannot read your key. kingo claude key list shows your names, and never a key.
  • Does the name live in my project? No. kingo writes nothing about the key into your project folder. The name belongs to your laptop, not to one project.
  • Can I use a name again? Yes, for every folder: write another folder in the line, and the same key pays there. Without a folder, kc --key website starts Claude Code for the course with this key; your flows in Langflow keep the key that they have.
  • What if I leave --key out? Then the start is as before, and your first OpenRouter key pays. A project does not remember its name: write --key and the name at every start of this project.
  • Can I change what is under a name? The model, yes: write --model again. The key, yes: kingo claude key add website asks whether another key shall take its place. The provider, no: one name, one provider. For a key at another provider, take another name.
  • And my first OpenRouter key? kingo claude key add --first puts another key in its place. Your first key stays until OpenRouter has accepted the new one.
  • Does it work with --login? No. --login uses your Claude subscription, and --key uses a key: kingo takes one of the two.

Your keys without a start. kingo also takes care of your keys when no Claude Code starts. So you can add a key once, and start every project with the short line, --key and the name:

You writeWhat it does
kingo claude key add websiteIt asks for the key and keeps it under the name, as the first start with --key does. --provider and --model go with it. No Claude Code starts.
kingo claude key listIt shows your names, each with its provider and its model. It never shows a key.
kingo claude key remove websiteIt deletes the key of this name from your laptop, with its provider and its model. At the provider, the key is as it was.

Three examples. Each one starts with something that you already have: a key, or a model on your laptop. In examples 2 and 3, write your own model and your own address into the line before you press Enter.

New here? What is different for you in the examples
  • You have no folder ~/projects/my-first-project? Then write ~/projects/practice in its place.
  • You use your Claude subscription with --login, and you have no key? Then your subscription pays already: read the examples, and try none.
  • kc --key website, without a folder, is the start for the course. You do not need it.

Example 1: a key for Anthropic’s API. You have a key from platform.claude.com. A workspace is a part of your account there that keeps the use of one project apart; every account has one, the Default Workspace. You choose the workspace when you make a key. The key must be for one workspace: kingo cannot use a key for all workspaces.

kc ~/projects/my-first-project --key api --provider anthropic --model sonnet

kingo asks for the key: Paste the Anthropic API key "api". Then it says where the model comes from: Claude Code's model comes from Anthropic's API, paid with your key "api", and The model: sonnet. Sonnet is Anthropic’s model for everyday coding. Without --model, Claude Code takes Opus, a larger model that costs more. In Claude Code, /model haiku changes to Haiku, Anthropic’s fast model for simple tasks, and /model sonnet changes back.

You have a Claude Pro or Max subscription? Then the subscription is usually the cheaper way. It has a fixed price per month, and Claude Code is included, up to the limits of your plan. Use your Claude subscription shows how.

Example 2: a model on your own laptop. You have Ollama, a program that runs models on your laptop, and a model in it. Ollama needs no key, so kingo asks for none: here, the name stands for the provider and the model. Start Ollama first, and write the name of your model in place of qwen3.5:

kc ~/projects/my-first-project --key local --provider ollama --model qwen3.5

kingo says: Claude Code's model comes from Ollama on this laptop ("local"). The model runs on your laptop, so no provider bills you. For Claude Code, Ollama asks for a model with a context window of 64,000 tokens or more. Your model holds fewer than 200,000 tokens? Then tell kingo once, with your number: kingo claude key add local --context 64000. kingo keeps the number with the name, and Claude Code keeps the conversation below it.

Example 3: a key from another provider, by its address. You have a key from a provider that you trust, and the address that this provider names for Claude Code. It works when the provider offers Anthropic’s Messages API, the format that Claude Code speaks. You write the address in place of a provider’s name, and you name the model. In this line, write the address of your provider and its name for the model in place of ours:

kc ~/projects/my-first-project --key work --provider https://yourtrustedkey.example.com --model big-model

The address is the one that the provider names for ANTHROPIC_BASE_URL. It ends in /v1 or in /v1/messages? kingo leaves this ending out, and says so: Claude Code adds /v1/messages itself. kingo asks for the key: Paste the key "work" for https://yourtrustedkey.example.com. kingo cannot check this key before the start. Your key, and everything that Claude Code sends to the model, go to this address: take only a provider that you trust.

Some providers need two more things, and kingo claude key add takes them: --context and a number of tokens, when the model holds fewer than 200,000 tokens, and --ca and a file, when the provider signs with a certificate of its own. kingo claude key help shows both.

We tested the three examples with a stand-in for the provider: not yet with a real key of Anthropic, a real Ollama, or a real provider.

Next time. When you start a project that may cost more than a little, give it a key of its own first.

From kingo-pod: ./kingo claude help, its lines on --key, --provider, --model and key. OpenRouter’s page on limits: “Per-key credit limits”, and what each key used. Anthropic’s pages Authentication: “Select a workspace”; Workspaces: “Every organization has a Default Workspace”; Model configuration: the names sonnet, opus and haiku, and that Claude Code with the Anthropic API “defaults to Opus 5.5”; Manage costs effectively: subscribers “have usage included in their subscription”, and “Sonnet handles most coding tasks well and costs less than Opus”; Connect Claude Code to an LLM gateway: its test request goes to the address of ANTHROPIC_BASE_URL plus /v1/messages. Ollama’s page Claude Code: “64k+ context window”.
