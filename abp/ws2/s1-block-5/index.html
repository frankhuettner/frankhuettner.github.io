Look inside WS2.3

  1. Open WS2.3 - Triage New Mail, then the tab Executions at the top: one line per run.

  2. Click the run of your mail. Double-click a node: on the left what came in, on the right what went out.

    StepNodeWhat it does
    Wake uptrigger_new_mail_notifyPostgresDB tells n8n at once: a new mail is here
    schedule_every_15_minuteslooks every 15 minutes too, in case that message got lost
    Take it oncefetch_and_claim_new_mailsnotes each new mail as taken, in the table processed; a mail already there is skipped, so no mail gets two answers
    Protectformat_mail_as_textthe mail as one text: sender, date, subject, body
    transform_mask_personal_numbersmasks card and bank numbers before any model sees the mail
    check_injectiona model asks: does the mail try to give the assistant orders? If so, a person looks at it
    Ask Triagefetch_triagesends the mail to your Langflow flow Triage and gets its answer
    check_triagen8n goes on only with an answer in order: checks_ok is true, and the action is one of the four. Anything else: a person looks at it
    Actpost_resultwrites Triage’s answer into processed, next to the mail
    if_confidentialthe fixed rule: a mail marked confidential only gets its label, whatever Triage proposed
    switch_by_actionone way out per action: a label, the archive, or WS2.4 for a draft. A person looks at anything else: label Assistant/Check
    How the wake-up call works

    When kingo-pod’s part called Mail writes a new mail into PostgresDB, the database itself sends a short message on a channel named n8n_workshop_mail_new. trigger_new_mail_notify listens on that channel: double-click it, and you see Listen For set to Advanced and the Channel Name. So WS2.3 starts within seconds, and nobody has to ask every minute whether something is new.

    It listens only while WS2.3 is published. When you click Execute workflow, it waits only 30 seconds for a new mail. If a message gets lost, for example while n8n restarts, schedule_every_15_minutes takes the mail a little later. Either way, fetch_and_claim_new_mails takes each mail only once.

Your own rule: an urgent mail gets a star

A mail whose subject says “urgent” gets a star in Gmail.

  1. Go back to the tab Editor.

  2. From the small dot on the right of the node check_triage, drag a line to an empty spot: n8n opens the list of nodes. Pick an If node and name it if_urgent. Set it like this:

    Paste this as the value on the left:

    {{ $json.subject }}

    Choose String, then contains, and type urgent on the right. Under Options, turn Ignore Case on.

  3. From its true output, add a Postgres node and name it post_star. Set it like this:

    Pick the credential Mail (n8n_workshop_mail_n8n) and Execute Query, and paste the query:

    INSERT INTO n8n_workshop_mail.changes (message_id, action, label) VALUES ($1, 'star', NULL);

    Under Options, add Query Parameters and paste this:

    {{ $json.message_id }}
    What else your rule can do in Gmail

    post_star writes one row into the table changes. kingo-pod’s part called Mail reads it, makes the change in your mailbox, and Gmail shows it seconds later. The row says what to do in two words: the action, then a label. NULL means: no label.

    In place of 'star', NULLWhat Gmail shows
    'star', NULLa star
    'unstar', NULLthe star taken off
    'read', NULLthe mail as read
    'unread', NULLthe mail as unread, in bold
    'label', 'Urgent'the label Assistant/Urgent
    'unlabel', 'Urgent'that label taken off
    'archive', NULLthe mail out of the inbox; it stays in All Mail
    'inbox', NULLthe mail back in the inbox

    For example, the label Assistant/Urgent in place of the star:

    INSERT INTO n8n_workshop_mail.changes (message_id, action, label) VALUES ($1, 'label', 'Urgent');

    The label is a word of your own: letters, digits, spaces, - and _, up to 40 characters. Gmail shows it under Assistant, next to the labels WS2.3 gives.

    No change deletes a mail or sends one. A change that failed keeps its row in changes, with the status failed and the reason in the column error.

  4. Click Publish again: n8n runs only the published version.

  5. From your SKKU account, send a mail with this subject. A little later it has a star in Gmail.

    Urgent: call me back

Done: your own rule runs in a real system. A rule decides here, not the model: the same every time.

Stuck? Import n8n/ws2_3_triage_new_mail_solution.json. It gives the finished workflow WS2.3 - Triage New Mail - SOLUTION, with the rule. In its node fetch_triage, check that Langflow (Run API) is picked; in its node submit_to_reply_with_approval, pick WS2.4 - Reply with Approval. Unpublish your WS2.3, then publish the solution: never both, or each new mail goes to only one of them. Help for block 5
